Do LLM Judges Penalise the Script?

Same Hindi content, native Devanagari versus romanized. Does the judge score it lower?

Date: 29 Aug 2026  ·  Target: ARR → ACL 2027  ·  Budget cap: $30 (tracked per call)  ·  Status: Lit review done (35 papers), pilot done, plan ready

1. The problem we are solving

Hundreds of millions of Hindi speakers type Hindi in the Latin alphabet: in chat, on social media, in voice transcripts. At the same time, the field now grades language models with other language models. These LLM judges sit inside leaderboards, reward models, and production quality gates.

Those pipelines silently assume one thing: that the writing system does not move the score. Nobody has tested that assumption. If a judge gives the same answer a lower score just because it is written in Latin letters instead of Devanagari, then every system serving romanized-Hindi users is being mis-ranked and mis-rewarded. If the judge is robust, that robustness deserves evidence instead of assumption. Either answer changes practice, and we pre-registered the direction: we predict romanized scores lower.

Why nobody has caught this

Prior work measures either (a) how well the model performs a task on romanized input (Script Gap, 2025: up to 24 points worse), or (b) how a judge scores identical content across different languages (Lower-Resource Higher Scores, 2026: up to 43% acceptance-rate shifts). Nobody has held the language fixed and varied only the script for a judge. Both major judge-bias taxonomies (CALM's 12 biases, JudgeBiasBench) do not even list orthography as a bias type. That is our slot.

3. The experiment

Four script conditions · four judges · one item per call · hypothesis never shown to the judge

The manipulation. We take about 150 to 200 Hindi instruction-and-response pairs at three quality tiers (high, medium, low), freeze them, and render each response in four orthographies. Content is identical in all four. Only the writing system changes:

ConditionExample ("how are you")What it represents
deva Devanagariकैसे हैं आपReference: the native script
iast IASTkaise haiṁ āpaScholarly romanization, deterministic
ascii Stripped IASTkaise haim apaPlain-ASCII romanization, deterministic
hinglish Naturalkaise hain aapWhat real users type; audited by a native speaker (you)

The judges. Each judge scores every item in every condition on a 0 to 100 rubric (correctness, completeness, helpfulness, clarity), one item per call so no judge ever sees two versions of the same item side by side.

The five analyses.

  1. Primary test. Paired score difference, deva minus each romanized condition, per judge. Wilcoxon signed-rank, bootstrap 95% confidence intervals, effect sizes, Bonferroni correction. This is the pre-registered test.
  2. Gradient test. Does the penalty grow as romanization gets less standard (deva → iast → ascii → hinglish)? Page's trend test.
  3. Quality interaction. Does the penalty concentrate in medium-quality items, where the judge has room to be swayed?
  4. Mechanism probe. Per item, correlate the token-inflation ratio (romanized tokens divided by Devanagari tokens) with the score penalty. This connects the tokenizer-fairness literature to the judge-bias literature for the first time.
  5. Mitigation. Add one line to the judge prompt ("evaluate the content regardless of script or orthography") and measure whether the gap closes. This gives practitioners something to do on Monday.

The paper survives every outcome

Penalty found: headline result, a new bias axis for the judge taxonomy. Null result: the first controlled evidence that frontier judges are script-robust, publishable because the direction was pre-registered. Mixed (likely, given our pilot): frontier judges robust, open judges not, and the gradient tells the story. Pilot 1 already ran (n=10, IAST only, Claude judges): +0.2 difference, near-null under the easiest conditions, which is exactly why the design above targets the harder ones.
